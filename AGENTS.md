# AGENTS.md

This file is the canonical coding-agent guidance for Pratfall. `CLAUDE.md` imports it.

## Project

Pratfall is a Python 3.13 CLI named `prat`. It runs one installed coding-agent command for one
prompt, selected through a built-in alias or a named global profile. `README.md` defines the public
CLI and configuration contracts.

## Commands

Use `just` for repository tasks:

```sh
just check
just coverage
just docs-build
just build
just test
```

`just check` runs Ruff lint and formatting checks, Pylint cycle detection, strict mypy, and all
tests, including the release helper tests under `scripts/`. `just setup` installs project
dependencies and repository hooks; it does not install `prat` globally. Local tool installation is
an explicit `just install-local` action.

## Architecture

The package uses an acyclic adapter boundary: immutable agent capabilities in `catalog.py`, config
loading and profile resolution in `config.py`, process lifecycle in `runner.py`, normalization in
`output.py`, and one command builder/output decoder per module in `adapters/`. `cli.py` owns parsing,
management commands, dispatch, and presentation. Internal modules import concrete seams rather than
the package root.

Keep the runtime standard-library only. Preserve argv-based subprocess execution, inherited native
authentication and permissions, bounded output, process-group cleanup, and normalized error exit
codes. Do not add retries, agent or model fallback, implicit login/install, shell interpolation, or
native config changes.

## Conventions

- Target Python 3.13, Ruff at 100 columns, strict mypy, and at least 80% branch coverage.
- New behavior gets observable tests in the matching `tests/test_<module>.py` file.
- Tests and release tests use fake agent/external commands and never spend inference credits.
- New code normally needs no comments or docstrings. Use names and small typed functions.
- Keep stdout for final text or one JSON result. Send progress and diagnostics to stderr.
- Treat configured command prefixes and native arguments as trusted input, while keeping prompts as
  argv or stdin data without invoking a shell.
- Update public guides and run `just docs-build` when the CLI or config contract changes.

Release details live in `docs/tech/release.md`. Never run the release helper, create a tag, publish a
release, change the Homebrew tap, or install a global command unless the user explicitly requests
that action. `CHANGELOG.md` is generated by git-cliff and should not be hand-edited.
